Incident Report: Wake Word Service Crash

Date: 2026-06-23

Component: WakeWordService.kt (Vosk Offline Acoustic Model)

1. Executive Summary

The offline wake word listener ("Hey Auto") is consistently failing to initialize, causing the WakeWordService to crash in the background. The crash is triggered by a fatal signal (SIGSEGV/SIGABRT) originating from the libvosk.so C++ binary. This prevents the Assistant from responding to voice activation.

2. Technical Analysis

Analysis of the device Tombstone logs reveals that the crash occurs the moment the Java layer instantiates the native C++ Recognizer:

F DEBUG : #00 pc 0000000000404548 /data/app/~~.../base.apk!libvosk.so (Model::Ref()+4)
F DEBUG : #01 pc 00000000003618ec /data/app/~~.../base.apk!libvosk.so (Recognizer::Recognizer(Model*, float)+88)
F DEBUG : #13 pc 0000000000073c10 /data/app/~~.../base.apk (org.vosk.Recognizer.<init>+0)

2.1 The FUSE & Android 14 Restriction

To reduce installation footprints, Android 14 (API 34) defaults the extractNativeLibs property to false. When this happens, the Android OS does not unpack .so (Shared Object) files into the app's internal storage (/data/data/com.example.gemininano/lib/). Instead, it maps them directly from within the compressed .apk archive.

While some Android JNI libraries can operate this way, Vosk relies heavily on direct filesystem paths to map its acoustic graphs, vocabulary vectors, and configuration files into RAM. When libvosk.so attempts to read memory pointers from a file descriptor that points inside an APK, it violates strict memory alignment rules, resulting in an immediate Segmentation Fault in Model::Ref().

3. The Resolution

The fix requires forcing the Android Package Manager to physically extract all native libraries to the filesystem during installation.

Applied Fix: Modified app/src/main/AndroidManifest.xml to explicitly include android:extractNativeLibs="true" inside the <application> tag. 

<application
    android:allowBackup="true"
    android:label="VehicleEdgeAssistant"
    android:supportsRtl="true"
    android:extractNativeLibs="true"
    android:theme="@style/Theme.MaterialComponents.DayNight.DarkActionBar">

4. Build Environment Correction

During the compilation of this fix, a secondary issue was encountered:

Issue Description
Gradle Daemon Mismatch The system's default JDK is Java 8, but Android Gradle Plugin 8.2.2 requires a minimum of Java 11 (optimally Java 17) to compile successfully.
Action Taken The compilation step was rerouted to utilize the explicitly installed Java 17 environment via JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64.
