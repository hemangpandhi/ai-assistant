Key Improvement Points & Reasons

1. "Prompt Bleed" Hallucination (The Test Failure Reason)

Issue: The LLM hallucinated <TOOL>playMusic(...)</TOOL> instead of triggering the climate control for "I'm freezing".

Reason: In LLMManager.kt (Line 218), the system prompt explicitly provides a hardcoded example: "Example: 'Playing relaxing music now. <TOOL>playMusic(relaxing music)</TOOL>'". Small Language Models (like the 2B Gemma model on the Tablet) suffer from "Prompt Bleed" where they rigidly copy the exact example provided in the system instructions when the context window is short. This perfectly explains why it output the exact phrase from the instructions.

Improvement Point: Change the system prompt example to use generic, abstract pseudo-code (e.g., <TOOL>actionName(parameter)</TOOL>) instead of a real tool to prevent the SLM from copying it.

2. Missing OpenCL GPU Hardware Acceleration

Issue: The app was silently falling back to the excruciatingly slow CPU backend (taking ~5-10s for TTFT).

Reason: Android 14+ strict native library loading prevented the Google LiteRT GPU Delegate from accessing the system's OpenCL drivers without explicit manifest declarations.

Improvement Point: Added <uses-native-library android:name="libOpenCL.so" /> to the AndroidManifest.xml, successfully unlocking GPU/NPU acceleration and dropping the TTFT to 1,733ms.

3. 2-Second Main Thread UI Freeze

Issue: The Voice Animation and UI would completely lock up while the LLM processed context.

Reason: The LLMManager.getSystemPrompt() was executing on the Dispatchers.Main UI thread, blocking all interface updates during the heavy Semantic Search phase.

Improvement Point: Wrapped the System Prompt assembly in withContext(Dispatchers.IO), fully unblocking the Main UI thread and restoring fluid 60FPS microphone animations.

4. Semantic Search Latency Overhead

Issue: Natural language queries lacking exact keyword matches forced the app to use a slow embedding model (adding 2000ms+ to the interaction).

Reason: The V2.0 JSON registry lacked synonyms for common tools.

Improvement Point: Injected conversational keywords (e.g., "freezing", "battery", "cold") directly into the JSON. Queries now hit the 0ms "Fast Path", completely bypassing the Semantic Search penalty.

5. Excessive Property IPC Overhead

Issue: The VehicleManager was tracking 1,044 hardware properties, causing memory bloat and massive system prompts.

Reason: The initial schema extraction pulled every conceivable VHAL property regardless of tool support.

Improvement Point: We aggressively pruned the registry down to the 9 actively supported properties. This minimized JSON parsing time, reduced the Context Window size, and lowered token-generation overhead.
